### Group 2 — backend service layer (8/8)
- `OfferLockedError` + `NoBillingEventError` exceptions. `OfferService._guard_writable` static helper enforces `status == draft` and is the first call inside every `select_for_update` block.
- `create_offer` snapshots `min_duration_months` / `notice_period_months` from the contract at create time. The 2.33.6 retry loop is preserved verbatim.
- `update_offer` accepts only the editable surface (validated against the classmethod), `select_for_update` + guard, recomputes line items / totals when `scoped_item_ids` changes (via the new `_apply_event_to_record` helper), regenerates PDF synchronously.
- `recreate_offer_from_contract` re-reads the billing event, raises `NoBillingEventError` when the contract was edited so the offer's `billing_date` no longer matches, overwrites only the contract-derived field set, preserves user-edited fields, preserves the existing `offer_number`.
- `finalize_offer`: idempotent on already-finalized, rejects `sent` + legacy statuses, transitions `draft → finalized` under row lock, then calls `attach_pdf_to_contract` inside the same transaction.
- `attach_pdf_to_contract`: looks up existing `ContractAttachment` by `source_offer=record` for idempotency, otherwise reads the PDF bytes once and creates a fresh row that owns its own file. Description language follows `tenant.legal_data.country`, NOT the customer language — the attachment is contract-local.
- `clone_offer_to_draft`: rejects draft sources, allocates a fresh offer number with the same retry-on-IntegrityError loop, copies every snapshot + user-editable field, sets `cloned_from=source`. Does NOT re-read the contract (per spec design decision — this is the "Copy" semantic).
- `send_offer_email_task` reworked: pre-check outside the lock, dispatch the email first (so SMTP failure leaves the draft fully editable), then transition `draft → sent` and attach under `select_for_update`. Concurrent Finalize → log loud and bail rather than overwrite state.

### Group 4 — PDF rendering (5/5)
- `apps/offers/markdown_render.py::render_markdown_to_safe_html` — Markdown→HTML→bleach allowlist (`p, br, em, strong, ul, ol, li, code, blockquote, h3, h4`), no attributes, no protocols, `strip=True`. Added `markdown~=3.7` and `bleach~=6.2` to `pyproject.toml`. Bleach's documented behavior: `strip=True` removes the tag wrappers but keeps text content. For `<script>alert(1)</script>` this means `<script>` is gone but `alert(1)` survives as plain text. That is *correct* for a PDF context (text is not executed) and the test now asserts the tag is gone, not that every byte vanishes.
- Two new template blocks: `offer-free-text after-items` between line items and totals, `offer-free-text before-terms` above the VAT sentence. Min-term and notice-period lines as bare `offer-notes` divs between totals and free-text-before-terms. All blocks are wrapped in `{% if %}` so they vanish cleanly when empty.
- Module-level `_render_minimum_term_line` / `_render_notice_period_line` helpers return the exact German + English wording from the spec, empty string when value is `None` or `0`.
- `backend/tests/test_offer_pdf_rendering.py` (23 cases): sanitizer behavior, min-term / notice wording, template-context wiring, and end-to-end Jinja rendering (WeasyPrint mocked out to keep tests fast and deterministic).
