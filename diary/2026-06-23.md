## Claude model ID — 5 hardcoded sites → single env-driven constant

User report: extraction failing with `Error code: 404 - {'type': 'error', 'error': {'type': 'not_found_error', 'message': 'model: claude-sonnet-4-20250514'}}`. Anthropic retired that snapshot. We had the same model ID hardcoded in 5 places: `apps/invoices/extraction.py`, `apps/invoices/pdf_analysis.py`, `apps/contracts/services/pdf_analysis.py`, `apps/banking/services/incoming_extraction.py`, `apps/assistant/views.py`.

### Decision: centralize behind ANTHROPIC_MODEL env var, pin to a specific snapshot

User asked if we could use a bare `claude-sonnet` alias. Anthropic doesn't accept that — they deprecated the `*-latest` aliases years ago precisely because silent model swaps caused production drift. The right shape is a single env-driven constant pinned to a specific snapshot, bumped via deploy when we want to take a new model:

```
ANTHROPIC_MODEL = env("ANTHROPIC_MODEL", default="claude-sonnet-4-6")
```

`claude-sonnet-4-6` is the current Sonnet snapshot per Anthropic's published model list. All 5 sites now read `settings.ANTHROPIC_MODEL`. Future bumps are a 1-line config or env override.
