### Decisions made during the frontend work
- **Auto-save on blur, not on every keystroke.** Each save triggers a server-side PDF regeneration (synchronous, ~500ms); keystroke-level save would thrash. Blur is a clean signal that the user is done with that field.
- **Scoped item editor deferred.** Backend `updateOffer` already accepts `scoped_item_ids`, but a multi-select UI against `contract.items` is a non-trivial component on its own. Per verify-pass Suggestion #2, we ship the rest first and add the picker as a follow-up.
- **Locked-state rendering uses the same MarkdownField component.** Just toggles a `readOnly` prop. Avoids divergence between draft and locked views of the same Markdown content.
- **No optimistic UI on the GraphQL writes.** The server is the source of truth; toast feedback after the round-trip is enough at this scale. Apollo cache update would force us to mirror the entire `_apply_event_to_record` logic in TypeScript, which is a guaranteed source of divergence.

### Bug caught: Django ORM trap in test
`contract.items.first().unit_price = X; contract.items.first().save()` — two `.first()` calls return two distinct instance copies. The price mutation on the first instance is silently discarded when the second instance is saved. Fix: capture the item in a local variable. Noted in test comment because this exact pattern reads as a fluent chain and is easy to miss in review.
